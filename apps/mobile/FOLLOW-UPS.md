# 후속 조치 목록

지금 고치지 않기로 **판단한** 것만 남긴다. 아직 모르는 것은 여기 적지 않는다. 해결하면 항목을 지우고 커밋 메시지에 근거를 남긴다.

## 전역 ErrorBoundary가 없다

**상태**: 미구현. `AGENTS.md` §5는 `_layout.tsx`에 전역 오류 경계를 두라고 규정하지만 아직 없다.

**지금 막고 있는 것과 아닌 것**

| 실패                      | 처리                                            | 근거                    |
| ------------------------- | ----------------------------------------------- | ----------------------- |
| DB를 열지 못함            | `DatabaseProvider`가 `onError`로 받아 복구 화면 | `database-provider.tsx` |
| 조회·저장 실패            | 값(`kind`)으로 반환해 화면이 분기               | `get-meeting-detail.ts` |
| **그 밖의 렌더 중 throw** | **없음 — 앱 전체가 흰 화면**                    | —                       |

**왜 미뤘나**: DB가 유일하게 확인된 부팅 실패 경로였고, 그건 전용 복구 UI로 막는 편이 정확하다. ErrorBoundary는 "무슨 일인지 모르지만 죽었다" 수준이라 맞춤 복구를 제안하지 못한다.

**해야 할 일**

- `_layout.tsx`의 `ThemeProvider` 안쪽, `DatabaseProvider` 바깥에 경계를 둔다(복구 화면과 같은 이유로 테마가 필요하다)
- 화면은 재시도 하나만 제공한다. 원인 문구는 사용자에게 노출하지 않는다(`UI_STRINGS` 고정 문구)
- dev 빌드에서는 red box를 가리지 않도록 `__DEV__` 분기를 고려한다
- 검증: 렌더 중 throw하는 임시 컴포넌트로 jest UI 테스트. E2E는 강제 수단이 마땅치 않다

**참고**: React ErrorBoundary는 **비동기 오류와 이벤트 핸들러 오류를 잡지 않는다.** effect 안 `await`에서 난 오류는 그대로 지나간다. 그 경로는 지금처럼 값으로 다뤄야 한다.

## iOS 실기기 E2E 수단이 없다

**상태**: Maestro가 실기기 iOS를 지원하지 않는다(공식 Known limitations). 현재 iOS는 시뮬레이터로만 자동 검증한다.

**지금 방식**: 시뮬레이터 E2E + 실기기 수동 확인.

**다시 볼 시점**: Maestro가 지원을 추가하거나, 실기기에서만 나는 문제(백그라운드 녹음, 실제 마이크 동작)를 반복적으로 놓치기 시작할 때.

---

## 권한 «거부» 상태의 화면을 실기기에서 증명하지 못한다

**상태**: 차단(다시 묻지 않음)은 E2E로 증명했다. 거부(재요청 가능)는 양 플랫폼 모두 자동화가 막혔다 — 자세한 사유는 `e2e/JOURNAL.md`.

**대체**: `recording-title-form.ui.test.tsx`의 denied 분기 + 수동 확인.

---

## iOS 시뮬레이터에서 마이크 권한이 꺼져 있으면 녹음 시작이 무반응

**상태**: 시뮬레이터 한정으로 확인. **실기기에서는 권한 없이 녹음 화면 진입 자체가 막혀 정상 동작한다.**

**왜 미뤘나**: 실기기 동작이 올바르고, 시뮬레이터 마이크 스택 차이로 보인다.

**다시 볼 시점**: 실기기에서 같은 증상이 재현되면 그때 원인을 판다.

## 정식 로그인 화면과 진입 경로가 없다

**상태**: 로그인·세션 유지·로그아웃은 UI Lab harness(`echonote://ui-lab`)로만 확인한다. 목업에 로그인 화면 명세가 없어 정식 화면을 만들지 않았다.

**할 일**: 목업에 로그인 화면(위치·타이포그래피·간격·접근성)을 추가한 뒤 `pages/sign-in`과 route를 만든다. 진입은 회의 목록 헤더의 계정 진입점과, 로그아웃 상태에서 전사를 요청할 때 띄우는 로그인 안내 두 곳이다. 앱 시작 시 로그인을 강제하지 않는다.

**다시 볼 시점**: G3-1(첫 서버 호출) 직전에 별도 checkpoint로 진행한다.
